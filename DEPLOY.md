# Deploying the Email Gateway

Current state: schema applied to Koyeb Postgres, 4 projects and 47 event policies seeded, Resend key valid, `smle-question-bank.com` verified, Gmail SMTP authenticated. `DRY_RUN=true`.

Run `npm run preflight` at any point — it proves every credential works without sending anything or spending quota.

---

## 1. Deploy to Vercel

Create a **new** Vercel project pointing at `email-system/`. Do not attach it to an existing project — the gateway must be able to redeploy without touching MEDQIZE or HR-.

Environment variables (Production). Copy the values from your local `.env.local`:

| Variable | Notes |
|---|---|
| `DATABASE_URL` | Koyeb Postgres, with `?sslmode=require` |
| `RESEND_API_KEY` | The gateway becomes the **only** holder of this. Rotate it after migration — it has lived in two repos. |
| `RESEND_WEBHOOK_SECRET` | **Currently a placeholder.** Replace with Resend's real value in step 3. |
| `MAIL_DOMAIN` | `smle-question-bank.com` |
| `GMAIL_SMTP_USER` / `GMAIL_SMTP_PASS` / `GMAIL_FROM_ADDRESS` | Gmail App Password. Carries all owner mail at zero Resend cost. |
| `ADMIN_KEY`, `DRAIN_SECRET`, `UNSUB_SECRET` | Already generated |
| `PRODUCTION_ORIGINS` | Add every real production hostname. Anything not listed gets **dropped**. |
| `PUBLIC_BASE_URL` | The gateway's own URL — used to build unsubscribe links |
| `DRY_RUN` | Keep `true` until you have watched a shadow week |

`vercel.json` already sets `regions: ["fra1"]` and the per-route `maxDuration` values. Note the Resend domain is verified in `eu-west-1`, so `fra1` keeps latency low.

After deploying, confirm:

```bash
curl -s https://<gateway>/api/v1/health
```

## 2. Wire the queue drain

Vercel Hobby crons run **at most once per day** (±59 min) — useless for a queue. Three layers, in order of importance:

1. **Opportunistic** — already automatic. Every authenticated API call drains a few due messages, so ordinary traffic keeps the queue moving.
2. **cron-job.org** (free, 1-minute granularity) — **this is the primary.** Create a job:
   - URL `https://<gateway>/api/v1/drain?source=cron-job-org`
   - Method POST, every 5 minutes
   - Header `Authorization: Bearer <DRAIN_SECRET>`
   - Enable its failure notifications
3. **GitHub Actions** — `.github/workflows/drain.yml` already exists; add repo secrets `GATEWAY_URL` and `DRAIN_SECRET`. Backup only: GitHub's free cron is often 10–60 minutes late.

A `{"skipped":"locked"}` response means another drain is already running. That is success, not failure.

## 3. Resend webhook

Resend dashboard → Webhooks → Add endpoint:

- URL `https://<gateway>/api/webhooks/resend`
- Events: `email.sent`, `email.delivered`, `email.bounced`, `email.complained`, `email.delivery_delayed`

Copy the signing secret it gives you into `RESEND_WEBHOOK_SECRET` and redeploy. **This is not optional** — it is the only thing keeping the shared domain reputation clean. All four projects send from one domain, so a bounce generated by one degrades inbox placement for all of them.

Verify with `npm run verify:live`, which signs a real bounce event and asserts the suppression is created.

## 4. Going live, safely

Nothing in any project has been changed yet. The order that keeps it that way:

1. **Shadow.** In each project set `EMAIL_GATEWAY_MODE=shadow` and pass its API key. The project's existing mailer still does the real sending; the gateway only records what it *would* have done. Run for about a week.
2. **Compare.** Every legacy send should have exactly one gateway record. The dashboard shows how many would have been deferred or dropped, and at which priority — **this is where you learn whether the budget survives, before any user is affected.**
3. **Cut over one project at a time**, riskiest last: `portfolio` → `game` → `HR-` → `MEDQIZE`.
4. Set `DRY_RUN=false` when the first project flips to `on`.

Rollback at any point is `EMAIL_GATEWAY_MODE=off` on that project. No code change, no gateway redeploy.

## 5. Raise the budget as you migrate

`daily_ceiling` is deliberately set to **40**, not 95. During migration both the projects and the gateway send, but the gateway only sees its own traffic — so it must leave room for the part it cannot see.

Raise it as each project cuts over:

```bash
curl -X POST https://<gateway>/api/admin \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"action":"set_setting","key":"daily_ceiling","value":95}'
```

Reserves are auto-scaled to fit whatever ceiling is set, so lowering it can never starve the lower priority classes. The dashboard shows both the configured and the effective reserve.

## 6. Watch

- **Dashboard** `https://<gateway>/` — quota burn-down, queue depth, recent messages, dead letters.
- **Uptime monitor** on `/api/v1/health`. It returns 503 when the oldest pending message is over an hour old, which is how you find out the scheduler has silently stopped.
- `npm run preflight` against production after any env change.

## Post-migration

Once every project is on `mode=on` and stable for 30 days:

1. Remove `SMTP_*` / `EMAIL_*` variables from all four projects.
2. **Rotate the Resend API key.** It has lived in MEDQIZE's and HR-'s repos; afterwards only the gateway should hold it.
3. Delete the legacy sender code paths.
